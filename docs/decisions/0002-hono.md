# 0002. Hono as the HTTP framework

- **Status:** Accepted
- **Date:** 2026-09-22

## Context
Two users, so raw performance doesn't matter. What matters is developer experience, type safety between API and web, and a small footprint.

## Decision
Hono on Node (`@hono/node-server`), with `@hono/zod-validator`. The web uses the `hc` RPC client with the exported `AppType`.

## Alternatives considered
- Fastify: mature, fast, has built-in pino. End-to-end typing with the SPA takes more work. It was a close second.
- Express 5: dated design, weak TypeScript.
- NestJS: heavy and ceremonial for this size.
- Elysia: Bun-first, and running Baileys on Bun is a compatibility risk.

## Consequences
- Follow Hono's guidance: no separate controller files, handlers inline, sub-apps mounted with `app.route()`, chained route definitions so `AppType` keeps its types.
- One Zod schema serves API validation, web forms and agent tool inputs.
